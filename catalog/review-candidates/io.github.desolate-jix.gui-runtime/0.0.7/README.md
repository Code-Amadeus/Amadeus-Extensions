## Repair scope and unchanged boundaries

Recommend [Runtime 0.1.10](https://github.com/Desolate-Jix/agent-gui-runtime/releases/tag/instant-v0.1.10).
Runtime settles failed controls only when their original producer records prove
a durable before-dispatch rejection, and successful `observe` through original
immutable capture/packet/ledger artifacts and terminal original input. A failed
control cannot conceal a reserved observation. Missing records, old error
strings, unknown input and partial writes are not zero-input proof. Legacy
rejected controls without original proof remain blocked; no new proof is
backfilled and no old journal is rewritten. Successful `recover` and
`resume_pre_dispatch` settlement remains unqualified.

The resource-only HTTP MCP + Skill connector recommends this separately
installed/configured/started/stopped/updated Runtime. Configuration, permissions,
contributions, runtime kind and Host engines are unchanged from 0.0.6. The two
tools `instant_recovery_preview` and `instant_recover_session` remain
operator-only after disconnection/owner conflict; Pi must not invoke them to
take over the old owner/workflow. Same-session Main bound-image review and
explicit continuation of the original job retain the existing input, identity,
freshness, geometry and cancellation gates.

The minimum HTTP protocol starts at 0.1.6; it is not a compatibility range or
qualification of future 0.1.x versions. Check actual Runtime/Host versions and
authenticated HTTP MCP, tool/schema, review/continue and cleanup capabilities.
Host Python 3.12 and Runtime's documented prepared API environment remain
separate. The API route needs no local GPU/model weights. Provider keys stay
in Runtime and provider calls may charge usage fees; the connector's secret
`connection_token` is a separate loopback authentication secret. Follow Host
enable/restart/new-Work requirements. Removing the connector does not stop or
uninstall Runtime or delete its data.
